# ADR-0025：实际使用驱动的仓库工作流

Status: Accepted design — 2026-10-25。所有者已批准完整接入 v1.1 及 E1：CI 强制检查＋所有者最终决定合并。
实现、远端迁移与合并后验收分别记录；最终候选必须提交所有者确认后才能合并。

## 问题

稳定的本地开发实例已经建立，后续能力应从真实工作中的阻力、错误和缺口演进。
仓库此前对 Draft 和 Ready 都运行约30–37分钟 Full，没有分阶段计划/报告、统一反馈表单，
也没有启用主线保护。只有一名维护者；不能把作者自审当作独立 GitHub approval。

## 方案

固定参考 Daedalus `git-github-workflow/v1.1.md`，完整文件 SHA-256
`de77bfd55da3811ed553985db8d61938467a2a3b2c0215e225b607428b667a86`。
该值是实际引用文件摘要，不是文件头中历史 reviewed-candidate 的摘要。

- 采用 PR-full / standard / v1。个人仓库不假设具备 Merge Queue；不实现 assured 或自动发布/部署。
- Draft 仅 Fast，不产生准入通过。Ready、Ready 更新和目标/描述编辑触发新的 Plan → Full。
  Full 保留现有格式/vet、race、真实渲染、冻结 OT-1、实验入口、数据契约与包装检查，
  将原 CI 单独执行的 Web OCI 一致性检查归入同一仓库 Full 入口。
- Plan 只生成数据，绑定 base/head/test SHA、tree、实际输入、策略/验证器摘要、环境与完整检查集合。
  选择器尚未证明，因此所有变更保守 Full，不引入 Affected/Full 双跑。
- 报告记录每项结果、耗时、环境、run/attempt、实际源对象；失败与取消不能产生通过。
  聚合检查验证完整报告、计划、当前 PR head/base/Ready 和标题。candidate-produced 报告仍依赖可信代码审查，
  不声称能够独立防御候选改写检查器或同 GitHub Actions App 内的恶意工作流。
- 主线经 PR、Squash、线性历史、必需版本化检查、严格 up-to-date、讨论解决、禁止 force/delete，
  不设置日常 bypass。运行中的部署分支不在这次规则范围内。
- 使用反馈 → 可验证的小步 PR → 原样制品 → 实际使用验收形成闭环；每步有独立事实，合并不自动关闭使用验收。

## 单维护者例外 E1（所有者已批准，2026-10-25）

当前唯一协作者为 `snkio027`，其本人 PR 无法获得有效的自身独立批准。
在单所有者、本地开发范围采用以下分工：

- GitHub 强制 PR、完整检查、最新 base、讨论解决、Squash、线性历史和无日常 bypass；关闭 auto-merge。
- required approving reviews 为 0，required Code Owner review 不启用。CODEOWNERS 标记策略责任，
  不将其报告成已强制的独立审查。不会用 Bot 或第二代理制造独立批准的表象。
- 代理可开发、验证、准备 PR 和修复审查意见；所有者审查最终 Diff、覆盖、风险与失败处置，
  并对具体候选作最终合并决定。日常开发无需逐步请示；不从“继续开发”推断合并批准。
- 候选交付至少包含 PR、head/base/test SHA、策略代次、CI run/attempt 及检查结果。
  head、base、受测 tree、质量策略或相关失败事实变化后重新核对，必要时重新验证和确认。
- 涉及权限、配置、部署范围、恢复或准入控制的变更仍须独立 ADR 审查；普通小修复不增加 ADR 仪式。
- 接受记录引用所有者的真实确认及对应候选；不由代理代写为所有者已审查或伪造 GitHub review。

人和本地代理目前共用 GitHub 身份，因此“所有者最后确认”是协作约定，**不是平台独立强制的身份边界**。
完整 CI 与无 bypass 也不能防止拥有规则管理权限的人改规则；管理员改规则须单独记录和审查。
standard 采用带此受控例外，不声称完整独立审查前提或 assured。

加入第二位有权 reviewer 后重新审查 E1，启用至少一次独立 approval、策略 Code Owner review 和过期批准失效。
扩展到多人、共享/生产环境或更高自治时先重新评估信任边界；需要防御候选伪造准入时须设计独立身份与验证来源，
不能把 E1 自动延伸到该范围。

## 生命周期例外 E2

保留实例部署分支与其证据。仓库不统一自动删除 head 分支；代码 PR 合并后由维护者检查
是否仍被依赖/被实例引用，再清理对应短期分支或 worktree。此例外避免把部署状态当成临时代码工作区。

## 验证和迁移

本地必须覆盖计划缺失/损坏、对象或环境不匹配、缺项/重复项、非成功结果、Draft、未知事件、
删除/重命名/未跟踪文件与失败留证。GitHub 必须实测 Draft → 无新 commit Ready、Ready 更新、
退回 Draft、取消、门禁失败及真实报告传递；本地模拟不代替这些平台证据。

先保存远端基线和无在途 PR 的事实，建立维护窗口，验证新 context 后再强制并核对规则。
旧的全部 Full 覆盖保留。源策略合并、远端采用完成和 CI 提速收益分别记录；没有基于相同条件的
实际成本对照前，不报告优化百分比。现有集群、凭据、部署树与已冻结运行计划不变。
